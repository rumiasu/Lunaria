# 微信适配与关闭边界

当前完成了不依赖真实凭据的客户端适配和离线测试，**未连接真实微信、支付或订阅通知**。应用仍只允许独立 H2 demo/test、127.0.0.1，不允许生产 profile、混合 profile 或 MySQL 数据源。加入凭据不会绕过这道启动约束，当前版本不能用于生产。

## 微信身份

`WechatCodeClient` 用 JDK HTTP 客户端调用固定 HTTPS `api.weixin.qq.com/sns/jscode2session`，编码 AppID、AppSecret、临时 code 和 grant_type。设置连接/请求超时，禁止重定向，拒绝 HTTP 错误、异常 JSON、服务错误与缺失 openid。不回退到 alice 或其他演示账号。code、session_key、AppSecret 不进入数据库、响应、异常原因或应用日志；只持久化 AppID/openid 与顾客的关联。

默认 `lunaria.wechat.enabled=false`，AppID/AppSecret 为空。显式开启且两项完整时才允许 code 交换；配置来源可为未提交的环境变量 `LUNARIA_WECHAT_ENABLED`、`LUNARIA_WECHAT_APP_ID`、`LUNARIA_WECHAT_APP_SECRET`。本次没有填写或创建真实凭据。测试只使用 fixture 配置与替代 HTTP transport。

| 接口 | 权限、输入 | 结果 |
|---|---|---|
| GET `/api/integrations/status` | 已登录 | production_ready=false；默认三项关闭；完整配置的身份项为 CONFIGURED_UNVERIFIED，表示配置完整，不代表联调验收 |
| POST `/api/auth/wechat` | 匿名可调用，必须 CSRF；`{"code":"临时凭证"}` | 默认 503；服务拒绝 code 为 401；未绑定为 409 WECHAT_BINDING_REQUIRED 与不透明 binding_id；已绑定只创建该顾客的 CUSTOMER 会话并更换 session ID |
| POST `/api/owner/wechat-bindings/{bindingId}` | 仅单店长；CSRF、Idempotency-Key；`{"customerId":"已有顾客ID","reason":"店长核对依据"}` | 将已验证身份关联已有顾客；事务、防重、审计；拒绝覆盖绑定、重复关联其他身份或合并资产 |

身份申请只创建待绑定记录，不创建顾客、不授予店长角色。店长必须先核对实际顾客，再保存关联；不能仅凭对方自报顾客 ID 绑定。重试相同防重键必须内容相同，已有绑定不提供直接改绑接口。AppID/openid 唯一，同一 AppID 下顾客关联唯一。记录在 V003 新表，历史卡、余额与规则快照不变。真实店长身份接入仍未验收，现有 owner 是受 demo/test 启动约束的开发身份。

## 订阅通知客户端

`WechatSubscriptionClient` 实现固定 HTTPS access_token 获取与 `message/subscribe/send`。token 只在内存缓存并提前过期；先调用可信 consent 检查，再请求 token/发送。接收人必须由服务端已有绑定取得，不能接受浏览器随意指定 openid。数据映射为 `data.<字段>.value`，只有服务端 errcode=0 才返回 providerAccepted；失败不会写“已发送”、不会自动重试造成重复通知，也不回退到日志冒充发送。

这只是可注入客户端，**没有自动注册发送 bean 或开放发送 HTTP 操作**。当前没有真实模板、订阅授权存储、一次性授权额度扣减和发送任务状态，因此 `/api/owner/integrations/wechat/notifications` 仍为 503。接入这些既定前置条件并验收后，才可由业务触发；不读取私人微信、不群发。

客户端构造时必须提供 `FailureRecorder`；正式接入应注入现有 `WechatNotificationAudit` Spring bean。客户端失败时保存一条 `WECHAT_NOTICE_FAILED` 审计，包含内部顾客 ID、固定失败码与“不自动重试”，独立 `REQUIRES_NEW` 事务使其不随调用方回滚。缺订阅授权、服务商拒绝、格式/传输错误均不会变成已发送；审计本身失败返回独立 `WECHAT_NOTICE_AUDIT_FAILED`，也不自动重试。不保存 openid、模板内容、token、AppSecret 或服务商调试文本。此记录只证明失败处理，不证明真实服务已接通。

## 微信支付 SDK 适配

依赖官方 [wechatpay-java 0.2.17](https://github.com/wechatpay-apiv3/wechatpay-java)，不自行实现加密算法。`WechatPaymentAdapter` 接收由调用方准备的官方 `JsapiService`、`NotificationParser` 与时钟；本轮没有构建真实商户配置、读取密钥或生成凭据，也没有 Spring bean 自动连接支付服务。

- `prepare` 将权威服务端待支付订单、绑定 openid、整数分金额、商户/应用和 HTTPS 回调地址映射为官方 JSAPI PrepayRequest，拒绝非法金额和 int 溢出。返回 prepay_id 只表示协议请求结果，不代表支付成功；尚未生成小程序调起支付参数。
- `verify` 先限制回调时间窗和输入，再调用官方 NotificationParser 验签解密，随后核对商户、AppID、订单号、付款 openid、SUCCESS 状态、CNY 与预期整数分金额。SDK 异常不会携带原始通知、密钥或内部原因返回。
- 返回的 VerifiedPayment 是适配结果；没有回调成功 ACK、订单落账、余额增加、发卡或退款副作用。不得直接用它当作已入账。未来必须先补权威在线订单、支付流水唯一约束、事务防重、异常查单/对账，再开启 HTTP 回调。

POST `/api/payments/wechat/prepay` 仍固定 503，不接受浏览器定价，不改资产。`/api/payments/wechat/notify` 未开放，不会返回假成功确认。真实支付、实际退款均未执行。余额购卡与人工退款处理记录仍为独立内部流程。

## 验收边界与来源

离线测试捕获 HTTP 请求并注入本地 JSON，支付测试 mock 官方 SDK 验证调用和字段检查；**不等同于真实 code、订阅权限、商户证书或密码学联调验收**。所有真实外部服务仍未接通。具体执行数量见本轮交付记录与测试摘要。

协议依据为微信官方 [code2Session](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html)、[订阅消息](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/mp-message-management/subscribe-message/sendMessage.html) 与上述官方 SDK。微信文档页面本轮抓取不可用，因此仍保留正式账号联调确认；SDK 类型和方法已按下载的官方 0.2.17 jar 核对。客户端封装和绑定业务为本任务新增；SDK 与框架是第三方依赖，不宣称业务全原创或已正式开通。
