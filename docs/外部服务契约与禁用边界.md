# 微信身份、支付、通知：当前契约与禁用行为

本轮补的是明确的**禁用适配边界**，不是已接通服务商的网络 SDK。没有凭据读取、外部 HTTP 请求、真实微信身份、预支付单、支付回调入账或通知发送。生产启动闸门继续拒绝 prod / 混合 profile / 非回环地址 / 非隔离数据源；仅填写一个 enabled 标志不会开通服务。

## 现在实际提供的接口

| 接口 | 权限及输入 | 未配置行为 |
|---|---|---|
| GET `/api/integrations/status` | 已登录顾客或店长 | 返回 production_ready=false，三项 enabled=false / DISABLED_NOT_CONFIGURED |
| POST `/api/auth/wechat` | 可匿名，仍需 CSRF；`{"code":"临时登录凭证"}` | 合法输入返回 503，不回退演示顾客、不建立身份；输入错误 400 |
| POST `/api/payments/wechat/prepay` | 顾客，仍需 CSRF | 503，不接受定价或造单、不扣余额、不发卡、不返回 prepay_id |
| POST `/api/owner/integrations/wechat/notifications` | 店长，仍需 CSRF | 503，不创建“已发送”记录、不执行外部发送 |

标准 503 响应：

```json
{"code":"INTEGRATION_NOT_CONFIGURED","feature":"wechat_payment","enabled":false,"message":"微信在线支付尚未接入；当前不调用外部服务、不创建身份或资金记录"}
```

角色或 CSRF 不满足时先返回 401/403。现有 GET `/api/session` 的 CSRF 引导方式不变。真正的微信支付回调 `/api/payments/wechat/notify` **没有开放**；它不会验签、解密、入账或返回成功确认，测试也确认不能得到 2xx 假成功。现有余额购卡与人工本金登记是独立内部演示流程，不是微信支付失败后的静默替代。

这些入口没有启用参数：未来需要正式实现身份映射、支付验签/幂等对账、订阅授权等适配后，再经过验收开放。当前不能把“已有路由”当作“只填密钥就能生产使用”。

## 必须外部提供及后续实现的边界

- 身份：已确认的应用主体与 AppID、服务端身份配置、店长受控绑定方式。微信临时 code 需要服务端验证并映射内部顾客，不能信任客户端 customerId 或把未知身份回退到 alice。当前不采集或记录真实 code/session_key。
- 支付：正式商户与应用关系、商户证书/密钥及 APIv3 配置、平台验签材料、独立 HTTPS 回调地址；后续须实现验签、解密、订单归属/金额核对、回调幂等及对账。当前没有创建账户、生成凭据或运行真实退款。[官方 Java SDK 的前置条件与回调能力](https://github.com/wechatpay-apiv3/wechatpay-java)仅作为后续接入参考，没有加入当前依赖。
- 通知：正式模板与场景、用户订阅授权和发送对象的内部映射；后续只能按已授权对象发送。没有私人微信读取、自动群发或“写日志就算发送”的替代。

微信官方 [code2Session](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-login/code2Session.html) 与 [订阅消息接口](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/mp-message-management/subscribe-message/sendMessage.html) 是后续依据；本环境未能读取其正文，所以不声称已完成最新参数或真实服务联调。秘密配置应通过本机未提交文件/环境提供，不进仓库。

本轮 8 项定向测试验证禁用状态、无身份回退、无资金副作用、权限、CSRF 和无支付回调假确认。前端没有改动，正式集成仍待上述配置与适配验收。
