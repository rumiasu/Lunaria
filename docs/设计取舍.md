# 工程设计取舍

## 最终以用户同栈要求为准

2026-10-23 已只读核对 `AquaFlow-backend/build.gradle`、`gradle/wrapper/gradle-wrapper.properties` 与两个小程序的 `app.json` / utils 文件名。采用 Java 17、Boot 4.0.6、Gradle 9.4.1、MyBatis 4.0.1、MySQL、原生小程序。只复用通用 Gradle wrapper 四个文件，业务、鉴权和界面均独立编写，无水站模块、复杂员工角色、多店或生产凭据。

此前曾最小核对[若依 fast POM](https://github.com/yangzongzhuan/RuoYi-Vue-fast/blob/master/pom.xml)、[MIT 许可](https://github.com/yangzongzhuan/RuoYi-Vue-fast/blob/master/LICENSE)、[若依 Vue3 package](https://github.com/yangzongzhuan/RuoYi-Vue3/blob/master/package.json)，见到 3.9.2、Boot 2.5.15、Java 8、MySQL/Redis 与桌面组件依赖；它们不是直接可用的美容手机产品，未启动实测。最早只在暂存区生成了 Boot 3.5.15 POM 候选，用户随后明确同栈，因此未继续 Vue/H5；旧 POM 作为决策证据保存 `evidence/superseded-pom.xml.txt`，不参与构建。Spring 官方 [系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html) 曾用于候选核对，最终版本以实际同栈工程为准。

## 单店先保证账务和预约边界

一个单体和一套数据库，应用服务是明确的事务边界，MyBatis 只接收绑定参数。所有写操作先取得单店设置行数据库锁，再检查持久化操作编号、执行状态转换和写流水。对一位店长的低并发业务，可读性比复杂分布式锁更重要；未来扩店需改锁粒度，不能直接复用此全局锁假称已支持。

卡权益与订单/预约项目名称、时长、金额快照保存。配置更新只影响未来购买和新预约；已有预约清单仍可见，调整有审计。金额不使用浮点；累计分摊避免总额丢分。财务事件保存来源与操作者，冲正追加事件。

## 明确的开发存储例外

目标数据库保持 MySQL，本轮本机主流程用隔离 H2 文件库，测试用 H2 MySQL 模式内存库。这样不申请或复用任何现有 MySQL 账号、不碰真实库；这不是 MySQL 实测证据。`backend/sql/schema.mysql.sql` 是独立目标 DDL。当前启动闸门不允许连接 MySQL，正式切换须先新建专用开发库/最小权限账号并跑同套场景，再显式改动受审查闸门。

## 身份与美术

公开演示身份必须通过回环服务的会话登录，API 服务端做角色及资产归属检查并保留 CSRF。生产配置在数据源初始化前拒绝，演示登录控制器仅 demo profile 注册；没有“传 customerId 就算本人”的绕过。

美术暂不定稿，token 与业务页分开。接下来应先在代表屏比较 2–3 种高端美容品牌方向，再扩全页，顾客端重视项目/套餐吸引力，店长端同视觉而操作清楚。
