## 已有且保留的退卡路径

当前首版售卡由余额购卡产生。扣余额、发卡和 PURCHASE 在同一事务；原购卡流水关联 card_id/source_id。退卡批准继续使用 REFUND_TO_BALANCE 回原顾客余额，退款流水 source_id 指向退款单，退款单再指向原卡和原 PURCHASE。没有现金或渠道退款，也不增加 RECHARGE / SERVICE / 履约累计。

本轮没有重写正确的退卡逻辑，只在退款详情增加 original_purchase_entries 与 refund_destination=CUSTOMER_BALANCE，直接呈现已有来源链，并增加定向回归。

## 补齐储值退出的最小流程

原来批准后仅扣余额预留，永远停留 RESERVED_NO_PAYOUT，缺少人工完成登记、取消预留和登记纠错入口。现新增店长 `POST /api/owner/balance-refunds/{id}/records`，沿用 CSRF、角色、防重和单店事务锁：

| 动作 | 结果 | 余额/来源 |
|---|---|---|
| NOTE（默认） | 只追加说明，可标记或明确解除争议 | 不改余额，不假结清 |
| RECORD_MANUAL | 完整预留金额及人工凭据编号，MANUAL_RECORDED | 不再扣余额；信息流水关联原预留 |
| REVERSE_MANUAL | 指定原人工登记，追加冲正，回到预留状态 | 不声称已追回外部资金，不自动恢复余额 |
| RELEASE | 确认未付款后解除预留，RELEASED | 仅恢复原预留金额，不记新充值 |

除 NOTE 外必须明确完整预留金额，不支持部分/超额，最多 100000000 分；与原申请上限、原预留流水、顾客和状态核对。同一申请只能有一个当前有效人工完成登记，同一原记录只能冲正一次，跨申请冲正拒绝。重复操作键复用原记录，竞争完成/解除只有一个动作成功。原理由、原试算、原凭据和旧事件均保留，事件按 revision 追加；余额/流水/记录/状态/审计/操作键同一事务。

争议可以只写说明保存。未决争议阻止人工完成或解除预留；明确记录核对结论后继续，不要求普通退卡增加多轮流程。人工完成后发生争议为 MANUAL_RECORD_DISPUTED，不计正常人工完成金额；可冲正，争议标志仍保留。返回始终注明 OWNER_MANUAL_RECORD_ONLY、provider_verified=false、external_transfer_executed=false。MANUAL_RECORDED 是店长人工凭据登记，不是服务商已付款确认。

summary 现在区分当前待处理/争议预留、无未决争议的人工完成、已解除金额和历史预留总额。人工完成/冲正的记录流水不再次改余额；解除预留才补回余额。所有这些不重复累计充值或消费，不能把不同 kind 的所有 amount_cents 相加当余额或营业收入。
