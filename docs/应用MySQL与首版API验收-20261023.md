## 本轮补齐

此前 `MysqlEngineTest` 直接装配 MyBatis/事务服务，只证明 SQL 与服务层行为，没有启动整个应用或 HTTP 服务器。本轮新增 `mysqlAppTest`：完整 `SpringApplication` 在随机回环端口启动，经实际 HTTP 会话、CSRF、控制器、MyBatis 和 MySQL 执行业务；还实际启动打包 jar，不能将这两类验收混同。

`mysql-it` 是隔离集成 profile，不是生产 profile。它只接受 `127.0.0.1` 的 `lunaria_it_<32位随机值>_app` 库、显式隔离标志和本次实例标记，禁用 H2 SQL 初始化、DemoSeed、演示账户及演示登录。应用核对测试实例标记后，按 V001–V004 执行打包内 SQL；`lunaria_schema_history` 保存版本、SHA256 和时间，迁移互斥，不降级、不自动接管无版本旧表，校验不一致即停止启动。DDL 可能隐式提交，失败不记录成功版本，不承诺 DDL 可整体回滚；临时库遇部分失败应重新准备本次实例。完整业务结构为 14 张表，另有实例标记和版本记录两张集成元数据表。

原店长只有演示登录，顾客微信入口不会授予 OWNER。本轮新增 `POST /api/auth/wechat/owner`：使用独立店长 AppID/Secret 交换 code，并与服务端预先指定的单个店长 openid 精确核对，之后才建立 OWNER 会话并轮换 session ID。顾客请求中的 role/openid 不参与授予权限；身份不符 403，缺配置 503，服务拒绝 401，审计失败不能登录成功。默认保持关闭，测试只用替代 transport，没有发送真实 code。

店长配置为 `LUNARIA_WECHAT_OWNER_ENABLED`、`LUNARIA_WECHAT_OWNER_APP_ID`、`LUNARIA_WECHAT_OWNER_APP_SECRET`、`LUNARIA_WECHAT_OWNER_OPEN_ID`，均未填写真实值。授权关联必须来自运营方已核对的本店身份，不提供公开自助店长注册或升级顾客角色。`GET /api/owner/wechat-bindings` 只供店长查询未绑定申请的内部编号、AppID 和创建时间，不返回 openid/session_key；原店长核对绑定接口继续保护资产归属。

同时去掉店长 `/catalog` 隐式借用演示顾客 alice 的依赖。全新 MySQL 库不含 alice/bob，店长仍可读取默认价目录并配置项目套餐；顾客目录按其独立等级取价。
