# Lunaria 云端后端接棒

仓库为 `https://github.com/rumiasu/Lunaria.git`，后续开发从远端 `main` 已推送提交接棒。保存环境、任务工作区与生产部署是不同操作；本轮只准备开发和测试，不部署生产，不使用 AquaFlow 的环境、配置、数据库或凭据。

## 保存环境的官方入口

设置 → Codex Cloud → Environments → Create environment；也可在新任务 Work in → Cloud → Select environment → Create environment。只选择 `rumiasu/Lunaria`，名称 `Lunaria`，保持私有、不添加秘密值。任务选择 `main`；不要在环境制作与本地发布分支同时修改代码。要求 Java 17、仓库内 Gradle 9.4.1 wrapper，以及独立临时 MySQL 8.4 测试服务。审核配置和准备报告后 Publish，再从该环境启动任务。

当前本地工具没有真实保存云环境的创建/修改接口；另一个 `finalize_environment` 工具明确是模拟环境目录，不能替代真实创建。本轮没有创建环境、没有环境 ID，也没有尝试新 OAuth、扩 GitHub 权限或修改安全设置。若界面要求这些操作，应停在具体提示处由用户处理。官方说明：[Cloud environments](https://learn.chatgpt.com/docs/environments/cloud-environments)。

后续有界入口检查尝试在隐藏浏览器打开 ChatGPT，打开超时，未进入环境管理页面；没有反复尝试。用户不再手动配合后，保留该断点，继续了独立 GitHub CI 验证。[实际成功的云端运行](https://github.com/rumiasu/Lunaria/actions/runs/39974858259) 已在 Linux / Java 17 / 临时 MySQL 8.4.13 完成边界测试、bootJar 与引擎测试，测试代码提交为 `20f1709c26908a3fede977a25bb4a3db31347c39`。这是 GitHub Actions，不是已发布的 Codex 保存环境。

## 无秘密值的准备与本地演示

在新环境中运行（首次需允许 Gradle 与 Maven Central 下载）：

```bash
bash scripts/prepare-backend.sh
cd backend
bash gradlew --no-daemon test \
  --tests cn.lunaria.WechatNotificationAuditTest \
  --tests cn.lunaria.WechatIdentityBindingTest \
  --tests cn.lunaria.ExternalIntegrationBoundaryTest \
  --tests cn.lunaria.integration.WechatClientsContractTest \
  --tests cn.lunaria.integration.WechatPaymentAdapterTest
java -jar build/libs/lunaria-dev.jar --spring.profiles.active=demo --server.port=0
```

最后一行只运行回环 H2 演示，不是生产启动；结束后停止该进程。已有启动闸门不放开，真实店长身份与正式 MySQL 初始化仍需后续独立实现和验收。脚本不安装或修改系统服务；Java 版本由 Gradle 17 工具链核对。

## 临时 MySQL 验证

Windows 上有 MySQL server/client 程序时，从仓库根目录运行：

```powershell
.\scripts\test-mysql-isolated.ps1 -MySqlBin '<MySQL程序目录>\bin'
# 依赖已缓存时可加 -Offline
```

脚本使用 `--no-defaults`、客户端 `--no-login-paths`、新建 `backend/build/mysql-it-*` 数据目录、随机端口与随机临时 root 口令，只绑定 `127.0.0.1`，不注册服务、不改宿主配置、不读现有库；结束时停掉本次进程并清理数据与口令。不要把此脚本改成连接已有服务。

Linux 云环境可直接运行仓库 `.github/workflows/backend.yml` 所定义的同等命令。CI 使用一次性 MySQL 8.4 服务和 tmpfs 数据目录，公开的 `lunaria-disposable-ci-only` 只是该临时服务的测试口令，不是账号秘密。若在独立云环境手动运行 `mysqlTest`，必须先准备自己的临时实例，再提供以下**临时进程环境变量**，绝不能填业务实例：

```bash
export LUNARIA_MYSQL_TEST_ISOLATED=true
export LUNARIA_MYSQL_TEST_URL='jdbc:mysql://127.0.0.1:<临时端口>/?sslMode=DISABLED&allowPublicKeyRetrieval=true&connectionTimeZone=%2B08:00&forceConnectionTimeZoneToSession=true'
export LUNARIA_MYSQL_TEST_USER='<本次临时用户>'
export LUNARIA_MYSQL_TEST_PASSWORD='<本次临时口令>'
cd backend
bash gradlew --no-daemon mysqlTest
```

测试只创建本次随机 `lunaria_it_*` schema，并只删除成功创建的这些 schema。检查真实迁移/完整结构、CHECK/外键/唯一约束、四线程购卡幂等与超扣、发卡 SQL 失败回滚、预约容量、分尾差/冲正及 DATETIME(6)。普通 `test` 不包含 MySQL 引擎测试，未显式声明隔离时 `mysqlTest` 直接失败。

`connectionTimeZone=Asia/Shanghai` 加强制会话设置，在未加载时区表的新 MySQL 上会报 Unknown or incorrect time zone。测试连接使用固定 `+08:00`（URL 中编码为 `%2B08:00`），验证上海墙上时间；不修改宿主时区表。

## 接棒边界

微信真实 code、正式店长身份、商户与回调、订阅授权额度/模板/发送状态、生产迁移版本记录仍未验收。支付回调校验适配已有，但权威在线订单、唯一支付流水、事务落账、防重 ACK、查单/对账尚未闭合，所以资金通知 HTTP 继续关闭。通知失败审计不等于已经发送通知，真实支付、退款、通知均未执行。
