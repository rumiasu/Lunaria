# 首版规则与待定项

## 已实现的业务边界

单店、单一受控店长、默认容量 1，可配置 1–5；顾客只能读取本人资产、预约与流水。项目时长 15–240 分钟，预约以 15 分钟为粒度、未来 30 天、上海时间。提交为 PENDING，店长确认时在事务锁内重新检查休息、暂停与峰值并发，确认才占用容量；待确认申请可能竞争同一时段。取消不扣次。调整保存原时间和原因；营业设置改变不会删除或自动取消已有预约。

店长可建新顾客档案和更新姓名/联系资料，新档案零本金、零履约、NORMAL / UNDECIDED。资料维护不改原余额、卡、等级、资格或身份绑定；联系资料仅店长可读。联系名单可按姓名/编号/联系方法搜索，按有效卡剩余次数 ≤ 1 筛选人工建议；不会自动发送消息。已验证微信身份仍由店长核对后绑定，不自动建顾客或合并资产。

套餐卡只含同一项目次数。默认套餐价格；VIP 只在该套餐单独设价时享专属价。余额、卡余次、等级独立存储。充值仅本金，购卡即扣余额并发卡，二者在一个数据库事务内。持久化操作编号绑定身份与请求内容；网络重试复用编号。金额为整数分，无浮点支付计算。

完成已确认且服务结束的预约才能核销；同一预约再次提交不再扣次。每次按 `floor(尚未履约的实付分值/剩余次数)` 分摊，最后一次吸收分尾差。冲正按被冲原流水金额添加 REVERSAL，不删除 SERVICE；余下分值仅在未用次数间重分摊，乱序冲正后再核销也不会制造或丢失 1 分。卡余次和履约参考累计同步回退，原预约标 CORRECTED。

已售卡的时长也属于快照权益：预约与时段查询可传本人 cardId，使用售卡项目名称/时长；不传时采用当前项目配置。核销拒绝时长短于旧卡权益的预约，不能通过调短项目时长悄悄缩水旧卡。

默认 `lunaria.membership.mode=TRACK_ONLY`，只记录 SERVICE / REVERSAL 的实付履约参考值，不自动升降级；显式 `DEMO_FULFILLED_VALUE` 才演示按门槛升级。正式累计消费认定仍待定。summary 把本金充值、购卡、履约参考、退款本金和利息分开，不能重复累计。

充值 RECHARGE 是资金流入；PURCHASE 是余额转卡权益；SERVICE 才是履约价值，不能把三项累加当“消费”。卡款退款使用 REFUND_TO_BALANCE，与原卡和退款申请关联，不再发现金。储值退款单独申请，人工确认后本金预留并记 BALANCE_REFUND_RESERVED / RESERVED_NO_PAYOUT；尚无实际付款或线下结算完成接口。

## 退款规则

默认对所有演示顾客采用更有利的实付比例，退款本金为尚未履约的原实付分值；分尾差与冲正严格追到 SERVICE / REVERSAL。例 9500 分、5 次、用 2 次退 5700 分。申请冻结该卡核销，审核拒绝恢复使用，批准后卡 RETURNED；重复审核不可重复入账。

消费者原因的原价扣已用算法仅保留受保护策略入口：必须有售卡时的 NEW_WITH_EVIDENCE 资格快照、ORIGINAL_PRICE_DISCLOSED 规则证据和合理原价记录；不得在退款时临时伪造售前规则。当前售卡不产生此类资格，普通界面不能启用原价追扣。金额下限 0，不产生补交债务。非消费者原因与争议禁止原价追扣；争议保留 PENDING，不自动选较少退款。

本金试算不是完整法律结算。普通退卡可直接按原试算人工审核，不新增强制协商、多轮确认或证据流程。人工处理入口仅说明必填，原因、拟议本金、利息、证据及顾客确认标志均可选；revision 只是审计留痕，原试算和原原因不可覆盖。争议、拟议少退或算法有争议的记录仍可保存、继续联系店长；结算时才检查原因已处理及适用规则保障。顾客确认标志不是门槛，利息默认 0，不自动计算法定利率。批准后本金与可选利息分流水回原演示余额，无外部付款。参考最高法正式解释[第 18–20 条及相关条款](https://www.court.gov.cn/zixun/xiangqing/459321.html)：非消费者原因按优惠权益核算；消费者原因须核对合理原价与更有利约定；不得追收超过预付的原价差额。代码用于隔离演示，不发布正式售卡条款。
